# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Go base for **PocketBook e-reader apps** (Linux ARM): a from-scratch vector widget library (`internal/toolkit/widget`, drawn with `fogleman/gg`), a thin cgo binding to the reader's `libinkview` (`internal/device/inkview`), and an app that installs its own launcher icon on first run. Developed and tested on a **PB741 (InkPad Color, 1404x1872, firmware 6.x; the Color 2 is the PB743)**. The README and `docs/` are in Brazilian Portuguese / English; the code and comments are English.

## Commands

```sh
go test ./...                                   # everything (run this before declaring anything done)
go test ./internal/toolkit/widget -run TestTable -v     # a single test / package
go vet ./...                                    # also catches `unkeyed fields` on geom.Rect: use geom.R(x, y, w, h)
go run ./cmd/preview                            # render the demo pages to preview-<n>.png (-page N, -w, -h)
go run ./tools/docgen                           # redraw docs/components/*.png from the real widgets
go run ./tools/docsync                          # refill code blocks in docs/ from examples/  (-check to only verify)
go run ./tools/bumpversion build|minor|major    # edit .version
.\build.ps1 [-App name]                         # Windows build -> dist/applications/<app>.app (bumps BUILD)
make dist [APP=name]                            # same on Linux/macOS/WSL
.\scripts\sonar.ps1                             # tests with -coverpkg + SonarQube scan (needs SONAR_GLOBAL_TOKEN)
.\scripts\install.ps1 -Drive F: [-All]          # developer copy of the built .app(s) to a USB-mounted reader
go run ./tools/appicons                         # write apps/<id>/icon.png from the icons the apps draw in code (a test fails when stale)
go run ./tools/coverage                         # coverage that counts, from coverage.out (-badge file.json writes the shields.io badge)
go run ./tools/release                          # stage the payload, build the installers + SHA256SUMS into ./release (after build.ps1 -All)
go run ./cmd/pbinstaller [-drive F:\]           # the installer for people (needs the staged payload)
```

Only `internal/device/inkview` needs the device; on the desktop it compiles to stubs (build tags `linux && arm && cgo`), so all UI logic is testable on the PC. `apps/*` only build for the reader, through Docker.

## Architecture (DDD, enforced)

The repo is organized by **bounded contexts** under `internal/`, with one dependency rule that `internal/architecture` checks (`go test ./internal/architecture`): dependencies point inwards (infrastructure → application → domain), every context may use the kernel, a context never reaches into another's insides, and nothing in `internal/` imports `apps/`, `examples/`, `tools/` or `cmd/`. A new top-level folder in `internal/` must be declared in `architecture.Contexts` (and its rules in `architecture.Rules`). The map and the glossary are the package doc of `internal/architecture`; docs chapter 14 explains it.

- **`internal/kernel`**: shared kernel, depends on nothing. `geom` is Rect/Point/Insets, `version` is MAJOR.MINOR.BUILD, `fold` compares text without case or accents.
- **`internal/toolkit`**: the UI library. **`widget`**: `Document` owns one element tree: `Layout()` -> `Render()`/`Update()` (grayscale `*image.Gray`) -> `HandlePointer()`. Every element embeds `Base` (ID, ClassName, Style, Hidden, Disabled, OnClick, Bounds...) and implements `Widget` (`Elem`, `Measure`, `Paint`); interactive ones also implement `PointerHandler`. One layout engine (`layout.go`) serves everything: a block is a vertical flex; measuring and arranging are pure functions over the tree. Custom elements outside the package must call `Base.Init(self)` and use `widget.Fire`. Long lists and texts are read by pages, not scrolled: `Pager` (any widgets, a page at a time) and `TextPager`. **`gfx`** draws in design units (`Canvas`, fonts, text, icons, images).
- **Coordinates are "design pixels"** (reference width 1404). `Document.Scale` converts to the real screen and touch is converted back, so drawing and touch share one space. Never offset or scale by hand.
- **Touch** (`dispatch.go`): down picks the deepest interactive, non-disabled element; move/up go to it (slider drag); a click is synthesized on release inside it, then `OnClick` bubbles up the tree. Modals and popups are drawn above; a touch outside a popup only closes it, a modal takes every touch. **Repaint** (`update.go`): `Update` diffs a snapshot of every element; the snapshot of what is inside a `Scroll` is taken as if it were at offset 0 (rounded to 1/1024), so a pure scroll changes nothing in it and `Update` slides the pixels of the window (`slide`) and paints only the uncovered strip and the bar; a popup/modal over it, a Scroll inside a Scroll or a jump past the window repaint instead. `Scroll.ScrollTo` rounds to whole device pixels so the slid pixels equal a full paint. `Document.LastUpdate()` gives the cost step by step. Text entry goes through the injected `Keyboard` interface (`FakeKeyboard` in tests/preview, InkView's keyboard on the device).
- **`internal/device`**: `inkview` (the only cgo; stubs on the desktop) `network` (the HTTP client for the reader's Linux, which has no resolv.conf and no IPv6: apps use `Env.HTTP`) and `desktop` (writes 128x128 8-bit BMP icons and text-patches the desktop `view.json`: backup, JSON validation, atomic replace, idempotent, repairs old relative paths; tested against a real firmware file in `testdata/`).
- **`internal/localization/i18n`**: pt-BR is primary, English the fallback (key -> language -> en -> pt-BR -> the key). Texts live in embedded `locales/*.json`.
- **`internal/platform`**: what an app is (`platform.RegisterOnDrive` does the first-run registration from the PC, for the installer). `domain` (Manifest, InstalledApp, Settings + ports), `application` (Runtime = device lifecycle with partial repaint, FirstRun), `infrastructure` (`jsonfiles` under `applications/.pbgo`, `reader` = InkView adapter + home screen registrar), and the package `platform` (composition root, the only import an app needs).
- **Automatic update (blueprint)**: `platform.Run` gives every app and the Launcher a background check (`application.Updater` + `Runtime.WithUpdates`; adapter `platform/infrastructure/selfupdate` reads the latest release's `catalog.json`): when online and the release's `catalog.json` `app_sha256` for this app differs from the SHA-256 of the installed `.app` (the checksum decides, never the version), a modal offers Update now / Later, downloads the zip (size + SHA-256 + ELF check), replaces its own `.app` and re-execs. The poll runs on the event loop (`Env.After`), the HTTP in one goroutine; `dev` builds never update; state per app in `applications/.pbgo/update/<id>.json`. `platform.RepoOwner/RepoName` name the release repository.
- **`internal/launcher`** is the Launcher context (`domain`: Tile/Grid/paging + the `AppLauncher` port; `application`: `Home`; `infrastructure/processlauncher`: starts an app with `execve`; `infrastructure/github`: the catalog (latest release's `catalog.json` + one `<id>.zip` per app); `infrastructure/appinstaller`: downloads the zip, checks SHA-256 and registers an app; `infrastructure/prefsfile` and `backgrounds`: the Launcher's preferences and the pictures to choose a background from, setting `PBGO_LAUNCHER` so the app returns to the Launcher when it asks to exit; `presentation`: the screens). `apps/launcher` is its composition root.
- **Registering = replacing**: `desktop.Register` (the app at its own start, the Launcher's install/update and the PC installer alike) rewrites the app's `view.json` entry whole in its place (path, title, icons; the key is put back in the group when missing) and rewrites the icon BMPs when they differ, so what an older version left is never kept; the same input changes nothing. The Launcher's icon cache keeps one picture per app (`<id>.png` + `<id>.src`, replaced when the release's address changes) and prunes what the catalog no longer lists.
- **Launcher shows the whole ecosystem**: `domain.AppsOf` merges the installed apps with the catalog's listings (`catalogcache` keeps the last `catalog.json`; the home fetches it in a goroutine and polls with `Env.After`), a tap on a missing app installs it, a **long press (2 s, `Base.OnLongPress`/`Document.LongPress` in the toolkit)** opens Update (only when the installed file's SHA-256 differs from the release `app_sha256`) / Install / Hide / Remove. Hidden ids live in `Preferences.HiddenApps`. Remove = `platform.Uninstall` (`application.Uninstall`: `desktop.Unregister` for view.json + icons, `jsonfiles.Files` for the .app/record/log/manifest `data`, manifest `shares` only when no other app shares them) plus `storage.EraseModule` for the `<id>_` tables of `productivity.db`. `Env.Root` is the storage root (a temp dir in tests: tests must never touch `/mnt/ext1`, which on Windows is `D:\mnt`).
- **`internal/installer`** is the Installer context (`domain`: Reader/Package/Outcome + ports; `application`: `Install`; `infrastructure`: `drives`, `embedded`, `readerfs`, `locale`; `presentation`: the console). `cmd/pbinstaller` is its composition root: it embeds `cmd/pbinstaller/payload` (staged by `tools/release`, not committed) and is released for Windows/Linux/macOS by `.github/workflows/release.yml` (a `v*` tag runs `ci.yml` first, then publishes one Release with every app, the installers and install commands in the notes; `ci.yml` is separate: vet, tests on Linux, coverage badge on `main`, apps built for the reader). It does not import the platform: the composition root passes it `platform.RegisterOnDrive`.
- **`internal/accounts`** is the Accounts context shared by the mail, tasks and calendar apps (`domain`: Account/Endpoint/Secret/presets + ports; `application`: `Accounts`; `infrastructure`: `jsonaccounts`, `securefile` = the AES-GCM vault with an optional PIN, `oauthdevice` = OAuth2 sign-in by device code). Depends on the kernel only. A `Secret` never prints itself: never log one.
- **`internal/mail`** is the Mail context for the future mail app (`domain`: Message/Folder/Draft/Address + reply and forward rules; `infrastructure/mime`: parse and compose messages with `go-message`; `infrastructure/sqlstore`: the `MessageStore` on the shared SQLite database, list rows without bodies, accent-insensitive search; `application`: `Sync` over the `Backend` port; `infrastructure/graph`: the Backend for Outlook.com/Microsoft 365 over Graph, plain HTTP+JSON; `imapmail`/`smtpsend`/`xoauth2`: the Backend for any IMAP server, SMTP sending and the XOAUTH2 sign-in). Depends on the kernel and `storage`.
- **`apps/mail`** is the first of the three productivity apps (IMAP with an app password for now): one document that shows the shared sign-in screen (`internal/accounts/presentation`, over `Accounts.Register`) until a mail account exists, then `internal/mail/presentation` over the `Mailbox` use case. Its data lives in `applications/.pbgo` (accounts, vault, `productivity.db`).
- **`internal/calendar`** is the Calendar context (`application`: `Agenda`; `presentation`: the screens of `apps/calendar`, which needs no account (the local account `local`) and reuses the toolkit's month `Calendar` with `Marked`/`OnMonth`; `domain`: Event/Occurrence/Calendar, `Occurrences` and `Expand` via rrule-go, a repeating event keeps its local time across DST; `infrastructure/icalendar`: `.ics` Parse/Write with go-ical, Windows time zone names mapped to IANA, problems become warnings). Depends on the kernel only.
- **`internal/tasks`** is the Tasks context (`application`: `Checklist`; `presentation`: the screens of `apps/tasks`, which needs no account (the local account `local`); `domain`: Task/List/Step, the smart views My Day/Important/Planned/Overdue, `Complete` that returns the next task of a repeating one). Depends on the kernel only.
- **Tasks sync**: `internal/tasks` has a `Backend` port (`infrastructure/graphtodo` = Microsoft To Do over Graph, `googletasks` = Google Tasks) and the `Sync` use case (send the outbox first, then bring the service's lists/tasks; ids of the service are prefixed `r:`; `sqlstore` keeps the outbox in `tasks_outbox` and `Raw()` is the view without it). `apps/tasks` links an OAuth2 account (`tasks-link.json`), `accountsui.NewConnect` signs in (Microsoft by device code, Google by `oauthcode` = authorization code + PKCE shown as a QR code from the toolkit's `NewQRCode`); client ids live in `applications/.pbgo/oauth.json` (`oauthconfig`). `internal/kernel/webjson` is the small HTTP+JSON client of the adapters.
- **`internal/bible`** is the Bible context of `apps/bible` (`domain`: Book/Version/Ref/Preferences, the built-in `Canon`, `FestiveVerse`, ports `Catalog`/`Library`/`Speaker`; `application`: `Bible` = refresh, resumable download, read a chapter, count what was read, resume, verse of the day; `infrastructure/midvash`: the Midvash API through `kernel/webjson`; `infrastructure/sqlstore`: the text one verse per row and the progress by place, without the version, in its own `bible.db`; `presentation`: Home, Bible, reader, settings). Memory rule: never load a whole version, a chapter at a time. The reader has no TTS API for apps (`Speaker` uses `flite`/`espeak` if present). Toolkit pieces made for it (and `widget.Scroll` — a window with a scroll bar onto taller content, the layout gives it no content height so it needs `Height`/`FlexGrow`, the paint clips its children, `widget.InView` for tests — and `widget.OAuthLogin`, the generic Google/Microsoft sign-in by device code or QR, shown in the hello app's Account page): `ParagraphPager`, the long-list behavior of `ComboBox` itself (when the options do not fit the screen its popup gets a search field and pages, and opens on the chosen option: no separate widget), `gfx.SetFamily`, `Document.SetInvert`. A download is a `Download` done one batch per `Step`, scheduled by the screen with `Env.After` (an InkView timer on the event loop) so touches are answered in between; never use goroutines to touch widgets. The language comes from `GetGlobalConfig` (`language=` in `/mnt/ext1/system/config/global.cfg`) and the clock from `system/timezone`.
- **Emulator and Engineering app**: `scripts/pbemu.ps1` (setup/start/install/shot/tap/swipe/log/crash, through WSL) runs the real PB741 firmware (6.8.4079, downloaded from PocketBook into `~/pbemu-work`, never committed) with pbemu, whose shim ignores the panel update ioctl (no A2/waveform/timing: measure those on the reader). `apps/eng` is the composition root of `internal/engineering` (its own `Panel` port; patterns, `TouchPad`, update-mode benchmark, scroll run, JSON-lines `Recorder` in `applications/.pbgo/eng.log`). The platform gives it `Env.Panel` (`DrawGray`/`DrawColor` in 24-bit B,G,R, `Wait`, `Settle`, `SetMode`) and the optional `platform.Raw` interface for an app that paints the panel itself; the platform does not lay out a screen the app paints, so such a screen calls `doc.Layout()` itself.
- **Online accounts**: `widget.OAuthLogin` is the one sign-in screen (Mail: Microsoft + Google; Tasks and Calendar: `accountsui.NewConnect`; hello's Account page), over `accountsui.OAuthProviders` and `oauthconfig.Sources` (client ids in `applications/.pbgo/oauth.json`). The `google` preset is Gmail (IMAP/SMTP, XOAUTH2) + Calendar + Tasks; `GoogleScopes` includes the restricted Gmail scope. Calendar sync is read-only (`calendar/application.Sync` over the `Backend` port, `graphcal` / `googlecal`: occurrences expanded, calendars read only, ids `<account>:<remote>`).
- **`internal/storage`** is the shared SQLite database (pure Go, `modernc.org/sqlite`) of the productivity apps: `Open` (TRUNCATE journal, never WAL: FAT volume), `Migrate(module, steps)` numbered 1..n in transactions, `EraseAccount`. It knows no domain: each context keeps its tables in it. Not yet run on ARM hardware.
- **`internal/showcase`** is the hello app's content, shared by `apps/hello`, `cmd/preview` and tests (translated, with a language switch).
- **Intents**: `env.Send(appID, "app.verb", data)` replaces the app with another, handing it a `platform.Intent` (`PBGO_INTENT`, max 48 KB: pass ids); the target declares `intents` in `app.json`, and on exit the reader returns to the app that asked (`domain.ReplyTarget`), not to the Launcher.
- **`apps/<id>`** are composition roots: `main.go` embeds `app.json` and calls `platform.Run`; `apps/hello` is the blueprint and `apps/contract_test.go` checks every app. They build to `dist/applications/<id>.app`.
- **`examples/`** holds the code samples of `docs/`, by context (`components`, `recipes`, `custom`, `translation`, `harness`); `tools/docsync` copies them into fenced blocks whose first line is `// examples/<package>/<file>.go` (the whole file) or `// examples/<package>/<file>.go#<Func>`, and `TestRepositoryDocsAreInSync` fails if a page is stale.

## Non-obvious constraints

- **Go 1.17 dialect** for anything that goes into the app (the Docker toolchain is 1.17.13): no generics, no `any`, no newer stdlib functions. Tools/tests run on newer Go but keep to 1.17 anyway.
- **Disable the system panel** (`inkview.DisablePanel()` in Init): otherwise InkView offsets the canvas ~137 px and drawing looks shifted.
- **Exit** must call both `CloseApp()` and `LeaveInkViewMain()`.
- **Desktop entry** (`system/profiles/default/config/desktop/view.json`; `system/config` is a link): the `path` of `U_<app>` must be **absolute**, icons may be relative, and the key must also be in a group's `apps` array. The home screen only reloads it when the USB cable is unplugged.
- **Fonts** (Go Regular/Bold) lack glyphs like "✓": draw an icon with `Canvas.Icon` instead.
- **Layout gaps to know**: no scrolling, `Pct` only for width, one page must fit the screen (the demo test fails on overflow).
- **Touch-accuracy rule**: a touch at the center of every interactive element must reach that element; `internal/showcase/demo_test.go` and `examples/components/components_test.go` enforce it, plus a 56 px minimum target.

## Environment quirks (Windows + WSL)

- Docker exists only inside WSL; `build.ps1` falls back to `wsl -e docker`. The user's PowerShell profile defines a broken `docker` function (drops arguments), so scripts only accept a real `docker` executable.
- Git Bash rewrites `/mnt/d/...` paths passed to `wsl`: run WSL commands through `pwsh -File x.ps1`. In PowerShell quote `"-coverprofile=coverage.out"`.
- Long multi-file shell heredocs sometimes fail to parse in the Bash tool; write files with the editor tools instead. Editing text files with `perl -pi` on UTF-8 content can double-encode it; use Node or the editor tools. Files checked out by Git are CRLF, so normalize `\r\n` before string matching.
- SonarQube runs on the Windows host (`localhost:9000`, token in `SONAR_GLOBAL_TOKEN`); containers reach it through the WSL default-route IP (handled by the scripts).

## Working rules for this repo (from the maintainer)

- **Each app has its own version** (`apps/<id>/.version`; the root `.version` is the release/tag): `build.ps1` runs `bumpversion -app <id> auto`, which bumps BUILD only when the code that app is built from changed (fingerprint on the file's second line); the release workflow runs `-app <id> check`; `catalog.json` carries the app's own version. An unchanged app keeps its version. Apps are built with `-trimpath -ldflags "-s -w -buildid="` so the same code gives the same bytes (measured: without them two builds of the same code differ, and the update check, which compares the `.app` SHA-256, would offer every app at every release); the stripped binaries have not been run on the reader yet.
- Versioning is `.version` = `MAJOR.MINOR.BUILD` (starts 1.0.0): every build bumps BUILD, a **finished task** bumps MINOR (BUILD -> 0), only big changes bump MAJOR. Tasks are the checkbox list in the README.
- **When a task is finished**: review and update the docs (`docs/en` and `docs/pt-br`, README tasks/architecture/links, `docgen` pictures, `docsync` + `-check`), mark the task, bump MINOR, run tests (and Sonar when code changed; the goal is 0 smells, quality gate OK), then **commit without being asked**. Do not push. Commit messages end with the `Co-Authored-By` trailer.
- **Never create git worktrees.**
- **Components are shared.** Every app uses the widgets of `internal/toolkit/widget`. A missing component is created there, generic and with no knowledge of any app (tests, an example in `examples/components`, docs, the touch-accuracy rule), never inside an app or a feature context. Check first whether an existing component, or a composition of them, already solves it.
- Apply SOLID/KISS/DRY pragmatically. Say plainly when something is untested on the device, and ask before changing anything on a connected reader outside its `applications/` folder (diagnostic code must be announced and removed).
